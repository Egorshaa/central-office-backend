## Backend для админ-панели центрального офиса.

## Стек: NestJS, Prisma, PostgreSQL, JWT, Docker Compose

## Что реализовано
- авторизация администраторов по email и паролю;
- роли ROOT и MANAGER;
- один активный сеанс на аккаунт;
- управление администраторами;
- владельцы магазинов;
- магазины;
- заявки на подключение терминалов;
- терминалы и heartbeat;
- смена пароля;
## Запуск
Открыть терминал (cmd ) :

- docker compose up -d --build

Проверка контейнеров:

- docker compose ps -a

При первом запуске автоматически создается root - пользователь

- После запуска: http://localhost:3000/docs
- Healthcheck: http://localhost:3000/health

## Первый вход
Локальные данные для входа:

- email: root@example.com
- pass: ChangeMe123!

Ручка:

- POST /auth/login

Тело запроса:

- {
  "email": "root@example.com",
  "password": "ChangeMe123!"
}

В ответе придут accessToken и refreshToken. Нужно скопировать accessToken. Далее нажать на кнопку "Authorize" в верхней части страницы и вставить токен без кавычек. Далее нажать на "Authorize".

## Роли
- Root
Может создавать менеджеров, менять пароль менеджера, удалять менеджеров, использовать остальные административные ручки.
- Manager
Может работать с владельцами, магазинами, заявками, терминалами. По условию, нет возможности создавать, удалять, менять пароль других админов.
## API
Все защищенные ручки требуют заголовок: 
Authorization: Bearer <accessToken>

## Авторизация
POST /auth/login - Вход администратора
POST /auth/shop/login - Вход магазина
POST /auth/refresh - Обновление токенов 
POST /auth/logout - Завершение текущей сессии

## Администраторы
GET /admins - Получить список админов
POST /admins - Создать менеджера
PATCH /admins/:id/password - Изменить пароль менеджера
DELETe /admins/:id - Удалить manager

## Владельцы магазинов
GET /shops-owners - Получить список владельцев
GET /shops-owners/:id - Получить данные конкретного владельца и его магазинов
POST /shops-owners - Создать владельца
PATCH /shops-owners/:id - Изменить владельца
DELETE /shops-owners/:id - Удалить владельца (по логике, владельца удалить нельзя, если к нему привязан магазин)

## Магазины 
GET /shops - Получить список магазинов
GET /shops/:id - Получить данные конкретного магазина
POST /shops - Создать магазин
PATCH /shops/:id/credentials - Изменить логин и пароль магазина (после изменения логина или пароля активная сессия магазина завершается)

## Заявки 
GET /requests - Получить список заявок 
POST /requests - Создать заявку
PATCH	/requests/:id/approve - Одобрить заявку
PATCH	/requests/:id/reject - Отклонить заявку
POST	/requests/:id/comment - Добавить комментарий

Пример создания заявки админом:

{
  "shopId": "uuid магазина",
  "macAddress": "AA:BB:CC:DD:EE:FF",
  "comment": "Подключить терминал"
}
Статусы заявки могут быть: PENDING, APPROVED, REJECTED.
При одобрении заявки терминал создается автоматически о статусом INACTIVE.

## Терминалы 
GET /terminals - Получить список терминалов
GET	/terminals/:id - Получить данные конкретного терминала
PATCH	/terminals/:id/status - Изменить статус вручную
POST	/terminals/alive - Heartbeat от магазина (POST /terminals/alive вызывается с JWT магазина, терминал должен принадлежать этому магазину)

## Профиль
PATCH /profile/password - Смена собственного пароля
Пример:

{
  "currentPassword": "CurrentPassword1!",
  "newPassword": "NewPassword1!"
}

После смены пароля текущая сессия завершается

## Как работает одна активная сессия

Для каждого админа и магазина в pgSQL хранится одна записать сессии. При повторном входе версия сессии меняется. Старые Accesstoken и refreshToken после этого работать перестают. 
То же происходит и после LOGOUT, смены пароля, изменения логина или пароля магазина. 

## Пароли

Пароли хранятся как bcrypt - хеши. и не возвращаются в API. Пароль ChangeMe123! используется только для первого локального входа. Для рабочего окружения пароль нужно заменить. 

## Основной сценарий
1. Войти под root через /auth/login.
2. Создать владельца через POST /shops-owners.
3. Создать магазин через POST /shops.
4. Создать заявку через POST /requests.
5. Одобрить заявку через PATCH /requests/:id/approve.
6. Проверить терминал через GET /terminals.
7. Войти как магазин через POST /auth/shop/login.
8. Отправить heartbeat через POST /terminals/alive.

## Остановка

Остановить контейнеры без удаления данных:
docker compose down
Удалить контейнеры и все данные PostgreSQL:
docker compose down -v
